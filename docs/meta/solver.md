# Solver

<!-- retie: skip -->

**Status:** rows built for plain claims, holders, say words, *because* (with holders, MAY, restrictors and *or*), contrary-to, MAY and *or*; jobs, CLI and browser entry shipped  
**Design authority:** [`docs/grammar/`](../grammar/introduction.md) through the [classification table](interpreter.md#classification-table). A row copies what a grammar anchor and its classification row already say; it never decides a reading.

The solver answers questions that take more than one step over a log: *does this follow*, *could this be*, *what clashes*, *what to give up*, *why not*, *what stands*. It translates the log's [readings](interpreter.md#terms) to a Clingo program and runs it with `clingo-wasm`. This note owns the encoding, the translation table, the jobs and their options, what each job returns, and the CLI. The one-step matcher, its steps and its switches stay in [interpreter](interpreter.md#matching).

Files: `src/interpret/translate.ts` (log to program), `src/interpret/solve.ts` (the jobs; the only file that imports `clingo-wasm`), `src/interpret/solve-browser.ts` (the browser entry), and `src/interpret/steps.ts` (step conditions shared with the matcher). Goldens are `src/interpret/fixtures/solve-*.lp`, each beside its `solve-*.txt` fixture.

## Adding a row

Each new row is confirmed by the user when it is written: the row, its classification table row, its grammar anchor, and a fixture that shows it. A construction with no row is left out and reported (see [the edge](#the-edge)); an agent never writes a row the user has not confirmed. A meaning that neither a grammar page nor the classification table states is an open decision for the user, not a row.

Every row keeps to the Clingo 5 / 6 common ground: no conditional literals in rule bodies, no `_` inside `not`, no integer division. Fitting is `match()`'s and step conditions are `steps.ts`'s; the translator never walks the parse tree. If a reading lacks what a row needs, the fix is a classification table row.

## Encoding

- **One predicate.** A claim is `holds(T)`, with every claim term inside it. A classification is `holds(isa(X, K))`, so a step rule can name the kind as a variable.
- **Denial is `holds(neg(T))`**, not `-holds(T)`: Clingo's strong negation forbids `holds(P), -holds(P)` in every world, so no `clash` atom could be derived.
- **Claim terms.** A plain claim is `<verbRoot>(z(..), d(..), b(..), g(K), w(dt(Key, Words), ..))` with only the roles present, where the translator writes root ids. A classification is `isa(Z, K)`; there is no `be(..)`. A list verb or a root whose name the encoding reserves is `act(Verb, ..)`.
- **Things.** A named thing is its root id. A first-mention noun is `nm(Id, Place)` (Place `z`, `d`, `b`, `d1`, …), one fresh constant per reading and role, with facts `holds(isa(..))`, `count(nm, V)` or `count(nm, rng(A, B, Hook))`, and `detail(nm, dt)`. Two readings of *a dog* are two dogs; a question still matches by root ([question filters](interpreter.md#question-filters)). A list is `ls(Id, Place)`.
- **Values.** `v(3)`, `pct`, `pts`, `rk`, `rke`, `cd`, `inf` / `ninf`, or `w("raw")` when the word has no value.
- **Readings.** A reading id is a Clingo string, and every translated reading gets a fact `on("t:0.2").` Every rule carries its `on(Id)`; a job swaps the fact for a choice to re-solve without it.
- **Fits.** `fits(Q, T)` means `match(Q, T)` succeeds: T says at least Q. Facts are computed before solving, against every ground term the log holds (stated claims, nested clauses, universal templates with their members). Slots: `c(Id)` (a hinge's condition), `o(Id)` (its outcome), `c(Id, M)` / `o(Id, M)` (the same for member M of a universal hinge, row 22), `i(Id, K)` (an item of a whole-list denial). Each slot is matched both ways against every ground term, and each denied term against every other term. **Conditionals** (R4e-2) meet by their slots, never their texts: for each ordered pair of conditional terms B ≠ A (stated, denied, wrapped or a question's), `fits(TB, TA).` when A has B's name or is an *iff*, the same outcome sign, and its slots say at least B's: for *if*, `match(cA, cB)` and `match(oB, oA)` (`match(oA, oB)` for a denied outcome); for *only if*, `match(cB, cA)` and `match(oA, oB)` (reversed likewise); for *iff*, both ways on both slots. The pairs are also `Translation.conditionalFits`. The generic clash rules then clash a denied conditional with one that says at least as much.
- **Provenance.** Each rule has a twin `fired(Id, C)` with the same body (C the `holds` argument; for other heads `notall(Id)`, `none(Id)`, `always(T)`, `count(..)`), and `used(Id, C, Premise)` for each `holds` literal in its body (not `member`, `fits`, `on`). *Why* is a walk over the answer set from a conclusion through `used` to the readings whose `fired` produced each premise.
- **Facts from steps.** `member(ls, X, Index)` (the index pairs *respectively*), `head(C, H)` chained, `less`, `same`, `within`.
- **Generic rules**, in every program:

  ```prolog
  clash(P) :- holds(P), holds(neg(P)).
  clash(Q) :- holds(neg(Q)), holds(P), fits(Q, P).
  holds(isa(X, H)) :- holds(isa(X, C)), head(C, H), switch(widen).
  holds(neg(P)) :- candidate(P), not holds(P), switch(closed).
  ```

  The widen rule has its `fired(widen, ..)` and `used(widen, ..)` twins.
- **Switches** are facts: `switch(widen)`, `switch(defaults)`, `switch(closed)`. Closed world adds `candidate(P)` for each term the log or the question mentions.
- **Lookups.** `Translation.terms` maps each ground term to its claim, so a question is matched in TypeScript; `inRange` decides a question's fit to a `within` fact.
- **Size.** A program text over about 1 MiB fails in `clingo-wasm`, whose fixed WebAssembly stack the text is copied onto; the jobs refuse it first (`maxBytes`). One `holds/1` keeps the rules one line each; a predicate per root grounds faster and waits until a consumer needs the speed.

Notes on the rows:

- **Only if (row 6).** A denied P rules out the condition only when the condition says at least P, so the fit runs from P to `c(Id)`; when the terms are equal this is the plain row.
- **Where the conditional has no term (rows 5 to 7).** A hinge over a say word keeps its rules with `on(Id)` alone. A hinge on a universal has the template and member terms of row 22. MAY with a hinge has a term (MAY rows 17 and 18). A first mention in the condition is written as its kind (R1-3), and its `slot:newMember` frame is used.
- **Whole-list denial (row 4)** joins each item on `fits(i(Id, K), Pk)`, so a claim that says at least the item counts.
- **Listed exceptions (row 15).** Any `unit:h` adverb in a `hual` / `hal` claim counts as listed exceptions (marker only), since the reader does not attach the occasions to the restrictor frame.
- **A hinge on a command** makes no claim (`causation.md#if`); the force frame has no row, so the turn is `beyond`.
- **Steps always on.** Membership and closed universal to instance always run in a solver job, since the pages state them as what the sentence says. `widen` stays a switch, named in the answer, since a compound's head is the lexicon's.

### Holders and say words

Each row reads one classification row and copies what its anchor states. A reply names the holder: *In Azozon's view these cannot all hold: b1, b2.* (`Clash.english`).

1. **A holder's view** (`xFamily:holder` with its host `overlay:evidential:th` or `overlay:may:th`; `holder.md#what-the-holder-covers`). `holds(view(H, T)) :- on(Id).`, a denial inside it `holds(view(H, neg(T))) :- on(Id).`, never `holds(T)`. The seam word's channel is data, `via(Id, Channel)`, outside the term, so two reports of one holder by different channels meet. One holder's views clash through the generic rules, wrapped: `clash(view(H, P)) :- holds(view(H, P)), holds(view(H, neg(P))).` and its `fits` form; two holders differ in `H` and never clash, and a view never clashes with your claim. The clash is the log's, so `clashes`, `giveUp`, `whyNot` and `both` see it.
2. **A carried holder** (`carry:holder`; `holder.md#naming-a-holder`): the later reading takes row 1 with the `H` of the reading it links to, and gives no `holds(T)`.
3. **Who the holder is.** A name is its root id; `-n` / `-ln` is `named` and keyed by root. A `-r` holder and the topic pronoun are pronouns (R4a-4; `holder.md#naming-a-holder`: "The holder may be the topic pronoun"): each resolves through `throughAntecedent` and uses its anaphor link, as a pronoun in a role does, so `xazozon theyomalen …` is Azozon's view; a first mention keeps its constant (`zodozel vudurul. zalazun theyomodozer vezuvel.` gives `view(nm(Id, z), ..)`), and a `-r` holder with no antecedent is the name it spells. The listener (`theyomawan`, R4a-5) is the turn's addressee term, as `zawan` is in a role (R4a-8: the one called, or `listener(N)`), an ordinary holder; the speaker is never a holder (`theyomuwen` is not a form). A kind of person or a bare kind (`theyomeyel`, *someone*) is a first-mention noun, `nm(Id, h)` with its `isa` fact, so two such holders are two people. The associative `-x` is `grp(R)`, the interlocutors (`theyomayan`) the turn's `we(..)` term (R4a-7, as `zayan` in a role), the generic pronoun `generic`: each its own holder, with nothing passing between them or into your claims. The generic view is one holder, so two generic views can clash.
4. **Inference inside one view** (`holder.md#what-the-holder-covers`: "Everything else in the clause, wherever it sits, belongs to the holder"). The holder's own stated rules (rows 4 to 11, 15, 18 and 21, and the *because* and *or* rows) run inside the view, each term wrapped; your own rules and claims never reach a view.
   - *If* (R4e-5): `holds(view(H, if(c(Id), o(Id)))) :- on(Id).`, then `holds(view(H, Out)) :- holds(view(H, if(c(Id), o(Id)))), fits(c(Id), P), holds(view(H, P)), on(Id).` and the back rule likewise. A denied conditional is `holds(view(H, neg(if(..))))` and clashes in the view through the generic `fits` form.
   - Universals and membership: the kind is the holder's too, `holds(view(H, isa(X, K)))` in the body.
   - *Not both* (R4a-2): `clash(view(H, notall(Id))) :- fits(i(Id, 1), P1), holds(view(H, P1)), fits(i(Id, 2), P2), holds(view(H, P2)), on(Id).`; `vel vul` / `vem vul` give `clash(view(H, notone(Id)))` the same way.
   - *No K* (R4a-3): `clash(view(H, none(Id))) :- holds(view(H, isa(X, K))), on(Id).`
   - Restrictors (R4a-1; "a sweeping *never* or *always* covers only the times you both remember"): `hual` gives `holds(view(H, T))` and the marker `always(view(H, T))`, `hal` gives `holds(view(H, neg(T)))` and `never(view(H, T))`, open `huam` row 10's choice on `view(H, T[X])`; listed exceptions, only the marker. Bare `ham` has no row.
   - A say word under the holder (R4a-13, the `say` × `holder` pair row): both wraps nest, `holds(view(H, say(W, P, R, A, E, T))) :- on(Id).`, stated or carried, and rows 6 to 8 run inside the view: `clash(view(V, say(.., u, ..)))`, `requires` and `bans` with every term wrapped. These lines join the program only when a reading holds a say word in a view. After *Alazun thinks the rules forbid it*, *does Alazun think the rules allow it?* answers *no*.

   `Clash.english` names the holder for each of these clash atoms.
5. **A say word** (`wordFamily:say`; `permission-consent.md#say-words`). `holds(say(Who, Part, Reach, Answer, Ending, T)) :- on(Id).` and no `holds(T)`: every say word is wrapped, consent too (the vow `zuwen vowurol hwuzal.` is consent with no act yet). `Who` is the hosted `bl-` word when there is one; else on `v` it is `sp("<turn speaker>")` for `-m` (`uwen` in a role is the same turn speaker; a question has no turn, so its speaker stays `speaker`), `rules` for `-l`, `unsaid` for `-r`; on `z`, `d`, `b` it is that role's filler. Pair reach `e` on `z` / `d` / `b` keeps its `bl-` word as a seventh argument, `to(X)`.
   - *A hinge over a say word* (R4a-9, the `say` × `hinge` pair row: the hinge and `blarth` first, `zalazun vezuyol. thohem blarth zazozon vowurol hwuval.`): rows 5 to 7 with the say term as the outcome and no conditional term, `holds(say(W, P, R, A, E, T)) :- fits(c(Id), C), holds(C), on(Id).` and back, `holds(neg(Cond)) :- fits(S, o(Id)), holds(neg(say(W, P, R, a, E, S))), on(Id).`, which a ban's denied permission (row 8) feeds. The condition stays your own claim.
   - *A binder over a say word* (R4a-10, the universal first, `zual godozel vowurol hwuval.`): row 8 with the head wrapped, `holds(say(W, P, R, A, E, T[X])) :- holds(isa(X, K)), on(Id).`, for every answer; the kind is your own claim, unwrapped. `zul` gives `say(.., neg(T[X]))`, open `zuam` row 10's choice. A `z` / `d` / `b` say word whose role is the fence takes `X` as `Who`.
   - *A say word over a universal or an* and *list* (R4a-11, D1): the whole stays one term, `holds(say(W, P, R, A, E, T[every(K)])) :- on(Id).` or with the list `ls(Id, P)`; for answers `a` and `o` only, one per member, `holds(say(W, P, R, A, E, T[X])) :- holds(isa(X, K)), on(Id).` or `:- member(ls(Id, P), X, G), on(Id).`, with `Who` = `X` when the list fills the say word's own part. A ban or `e` is the whole term only (forbidding *both walk* does not forbid each). `zul`, open `zuam` and a denial list under a leading say word have no row.
   - *A say word over a hinge, because, MAY or a contrary zone* (R4a-12, D1; the say word earlier in the text, `hwuval zazozon vowurol thohem blarl zalazun vezuyol.`, and also `zazozon vowurol hwuval thohem blarl …`, since the hinge keeps its clause last): data, `holds(say(W, P, R, A, E, D)) :- on(Id).` with `D` one of `if(C, O)`, `onlyif(C, O)`, `iff(C, O)`, `because(C, O)`, `may(T)`, `against(T, Z)`. No part holds, no MAY choice, no hinge rule. `D` is not pooled, so even a question asked as said answers *unknown*.
6. **Which say words clash.** Same `Who`, `Part`, `Reach`, `Ending` and a fitting act, with answers `a` and `u`, or `o` and `u`: `clash(say(W, P, R, u, E, T)) :- holds(say(W, P, R, a, E, T)), holds(say(W, P, R, u, E, T)).`, the `o` line, and the `fits` forms. Another party, source, ending or reach never clashes; `e` (*their call*) clashes with nothing. A standing grant and this episode's ban, or two parties, stand together.
7. **A requirement gives permission.** `holds(say(W, P, R, a, E, T)) :- holds(say(W, P, R, o, E, T)).` (`fired` id `requires`). After *the rules require Azozon to walk*, *may Azozon walk?* answers *yes*.
8. **A ban denies the matching permission** (user, 2026-11-19; `permission-consent.md#requirement`: "A ban takes permission away"). `holds(neg(say(W, P, R, a, E, Q))) :- holds(say(W, P, R, u, E, T)), fits(T, Q).` and the plain form, `fired` id `bans`. After *the rules forbid Azozon walking*, *may Azozon walk?* answers *no*, citing the ban (`hits` reads a wrapped `neg(say(..))`). A requirement plus a ban still clashes.

### Because, fault and contrary-to

10. **Because** (`overlay:clause_hinge:th` / `:g` with gloss `because`; `because-and-iff.md#choosing-a-hinge`): `holds(Out) :- on(Id).`, `holds(Cond) :- on(Id).`, `holds(cause(Cond, Out)) :- on(Id).` *Enough* adds no rule while both sides are claimed. A first-mention noun in the condition reads as its kind (no `isa` facts).

   - *The hinge over MAY* (R4b-6, D11; the hinge and `blarth` first, `thahum blarth thomam …`): `holds(Cond)` (the earlier sentence, through `standInBack`), `{ holds(Out) } :- on(Id).`, `holds(may(Out))`, `holds(cause(Cond, may(Out)))`.

11. **Not because** (`joinSeries:u` in the hinge's stance list; `verb-and-stance-joins.md#stance-joins`): `holds(Out) :- on(Id).` and `holds(neg(cause(Cond, Out))) :- on(Id).` The condition stays unstated: no `holds(Cond)`. 13. **Only because** (`thebem` then `thahum`): row 10 plus row 6 on the same condition. A stacked `thebem` with no `/b/` of its own shares the following `thahum`'s `hosted` term, and links its own `grounds` when the condition is the next sentence. On a noun (R4b-3, `zerulal gebem gahum blugalal.`) the two hinges are the outcome noun's details: the translation table's row 20 for *because* (both `isa` claims and `cause(..)`) plus `holds(onlyif(c(Id), o(Id)))` and its back rule. A name as the outcome (`zazozon gahum blerulal.`, `zazozon gebem gahum blerulal.`) stays left (R4b-8, D15).
14. **Contrary to** (`hookJob:zone`, frame:contrary; `contrary-to.md#contrary-to-holder`: "the event is still your claim"): `holds(T) :- on(Id).` and `holds(against(T, Z)) :- on(Id).`, with `Z` = `plan(H)`, `want(H)`, `decision(H)` (R4b decision 3), `channel(Gloss, H)`, or `say(W, P, R, A, E[, to])`. ### MAY and *or*: worlds

MAY and *or* make several worlds, so MAY alone never makes anything follow.

15. **MAY on a claim** (`overlay:may:th`; `knowing.md#may`): `{ holds(T) } :- on(Id).` plus `holds(may(T)) :- on(Id).` (under a MAY holder, `may(view(H, T))`). The ending (`thomal`, `thomam`, `thomar`) adds no rule and is kept in `Translation.notes`. Possibly not (`joinSeries:u` on the verb under MAY): `{ holds(neg(T)) } :- on(Id).` MAY denied (`thomam thul`, `joinSeries:u` in the stance list): row 1's `holds(T)`, frame in `notes` as row 16.
16. **A holder on MAY**: `{ holds(view(H, T)) } :- on(Id).` and `{ holds(view(H, neg(T))) } :- on(Id).`; a later bare sentence it carries to is a plain view. The holder's own MAY is the wrap flag `Wrap.may`, writing `holds(view(H, may(T))) :- on(Id).`, which never meets `view(H, T)` or `view(H, neg(T))`; row 4 does not run on it. A carried holder on a MAY sentence is the holder's own MAY too (R4b-27, D6; `holder.md#naming-a-holder`; `zalazun theyomazozon vudurul. zalazun thomam vezuvel.`), on a plain claim only: beside a hinge, *because*, a universal, a restrictor or a say word it stays left.
17. **MAY over an *or* list** (text order over a list term): a gate `{ maybe(Id) } :- on(Id).`, and every rule of the content takes `maybe(Id)` beside `on(Id)`. **MAY over a hinge** (R4e-6; order `overlay:may:th > overlay:clause_hinge:th`): row 15 on the conditional term, `{ holds(if(c(Id), o(Id))) } :- on(Id).` and `holds(may(if(c(Id), o(Id)))) :- on(Id).`, with no `maybe(Id)` gate, since rows 5 to 7 already wait on the term (`thomam zalazun vehohel thohem blarl zazozon vowurol.`). **A hinge over MAY** (the `blarth` hinge first; its condition resolves through the `standInBack` link, `byId`): the term `if(c(Id), may(o(Id)))`, held plainly, then row 5's forward rule as a choice, `{ holds(Out) } :- holds(if(c(Id), may(o(Id)))), fits(c(Id), P), holds(P), on(Id).`, and no backward rule. *Only if* over MAY (R4b-26, D5, R4b decision 1, D19; `zalazun vezuvel. thebem blarth thomam zazozon vowurol.`): `onlyif(c(Id), may(o(Id)))` and row 6's forward rule, plain (without the condition the outcome is not even possible), `holds(neg(Out)) :- holds(onlyif(..)), fits(P, c(Id)), holds(neg(P)), on(Id).`, and no backward rule. A held condition gives the same choice on the outcome under *only if* too (D19: MAY gives a choice wherever it is held), so *could Azozon walk?* is *yes*. The `may(..)` wrapper keeps *if A, maybe B* from meeting *if A, B* (`Conditional.may`).
   - *Over members* (R4b-18; `knowing.md#may`: "The sentence now says the leaving is possible, not that it happens"): the gate over row 11, the list claim and `holds(T[X]) :- member(ls(Id, z), X, G), maybe(Id), on(Id).`, with `holds(may(T))` on the list term, ungated (`zazozon zalazun zal thomam vowurol.`).
   - *Over a whole-list denial* (R4b-19): row 4's `clash(notall(Id))` and row 21's `clash(notone(Id))` with `maybe(Id)` in each body (`zazozon thomam vowurol veruvol val vul.`), so the world without the gate is clash-free.
   - *Over a say word* (R4b-20; `knowing.md#may` with `clause.md#which-covers-which`; MAY first, `thomam zazozon vowurol hwuvam.`): row 15 on the wrapped term, `{ holds(say(W, P, R, A, E, T)) } :- on(Id).` and `holds(may(say(W, P, R, A, E, T))) :- on(Id).`; Holders rows 6 to 9 run in the worlds that take the choice. The say word first (`hwuvam … thomam`) stays Holders row 5's data, `say(.., may(T))`.
   - *With a closed universal* (R4b-21; `usually-vs-must.md#how-things-work`: "*Maybe every cat sleeps* is MAY on the same clause"): MAY first, one gate over row 8 for the whole generalization, `holds(T[X]) :- holds(isa(X, K)), maybe(Id), on(Id).` (`thomam zual godozel vowurol.`); the binder first, a choice per member, `{ holds(T[X]) } :- holds(isa(X, K)), on(Id).` and `holds(may(T[X])) :- holds(isa(X, K)), on(Id).` (`zual godozel thomam vowurol.`). `zul` with a verb takes the denied head; open `zuam` and *no K* with no verb have no row.
   - *Over bare `hual` / `hal`* (R4b-22; `knowing.md#may` with `clause.md#which-covers-which`): the gate over row 15, `holds(T) :- maybe(Id), on(Id).` and `always(T) :- maybe(Id), on(Id).`; `hal` the same with `neg(T)` and `never(T)` (`thomam zazozon vowurol hual.`). Open `huam` has no row.
   - *`hual` over MAY* (R4b-23, D13; `restrictors.md#always-hual`; `hual zazozon vowurol thomam.`): `holds(may(T)) :- on(Id).`, the marker `always(may(T)) :- on(Id).`, row 15's choice `{ holds(T) } :- on(Id).` (D18, so *could Azozon walk?* is *yes*), and `clash(always(may(T))) :- never(T), on(Id).` and its `fits` form, `clash(always(may(T))) :- never(P), fits(P, T), on(Id).` A plain denial `holds(neg(T))` never clashes with it. `hal` or `huam` over MAY, and listed exceptions, have no row.
18. **MAY on a hinge's condition** (`causation.md#if`): the condition is the possibility. A stated T gives `may(T)` by a rule inside each hinge with a MAY condition, not one generic rule (that would loop `may(may(..))`); the hinge's body takes `holds(may(T))` in place of `holds(P)`. The term is `if(may(c(Id)), o(Id))` (R4e-6). No `holds(may(T))` for estimates or for a hinge over MAY. A stated *not T* does not withdraw it. *Only if* and *iff* (R4b-25, D5; `zazozon vowurol thebem blarl zalazun thomam vezuvel.`) take the same body: row 6 reads `holds(neg(may(P)))`, and its back rule gives the condition as MAY on a claim (row 15), `{ holds(Cond) } :- holds(onlyif(may(c(Id)), o(Id))), fits(o(Id), P), holds(P), on(Id).` and `holds(may(Cond))` from the same body. *Iff* adds no back rule for its *if* half.
19. **Degrees** (`thraremol`, `th+`, `th+100`, `th+0`; `th-` too): an estimate is row 15's choice with the figure as data, `likely(Id, V)`, so a 0% estimate still *could be*. `thrawal` (certain) is a plain claim and `thramowal` (no chance) a denial.
20. **The *or* bounds** (`joinSeries:e`, `joinSeries:ae`; `joins.md#choice-e`, `set-joins.md#exclusivity-and-denying-a-whole-list`): `el` exactly one, `em` at most one, `ael` and `aem` at least one ("On `ae`, even `-m` still needs at least one of the listed items"). Each item k of the reading's list term is a choice, `{ holds(T[k]) } :- on(Id).` (no `member` facts), and the bounds are clash atoms plus plain rules, no hard constraint, so a log that breaks a bound keeps a world with a `clash` atom. For `el`, `ael` and `aem`: `some(Id) :- holds(T[k]), on(Id).` per item and `clash(noneof(Id)) :- on(Id), not some(Id).`, plus `holds(T[k]) :- holds(neg(T[j])), …, on(Id).` with every other item denied. For `el` and `em`: `holds(neg(T[j])) :- holds(T[k]), on(Id).` per pair. Each joins on `fits(i(Id, K), P)`.
21. **Whole-list denial of an *or* list** (`joinSeries:u` over a closed `e` / `ae` list): `vael vul` denies at least one, each item denied; so does `vaem vul` (R4b-24; `set-joins.md#exclusivity-and-denying-a-whole-list`: "On `ae`, even `-m` still needs at least one of the listed items"), so `zazozon vowurol veruvol vaem vul.` is *neither*. `vel vul` (not exactly one): for each item k, `clash(notone(Id)) :- holds(T[k]), holds(neg(T[j])), …, on(Id).` with every other item denied, joined on `fits(i(Id, K), P)`; with two items also `holds(T[2]) :- holds(T[1]), on(Id).` and `holds(neg(T[2])) :- holds(neg(T[1])), on(Id).`, both ways. `vem vul` (at least two) adds the same clash with no item held.

New reserved names: `we`, `every`, `because`, `if`, `onlyif`, `iff`, `bans`, `cause`, `fault`, `share`, `plan`, `channel`, `maybe`, `likely`, `some`, `noneof`, `notone`, `may`, `view`, `say`, `grp`, `interlocutors`, `generic`.

### Which worlds a job reads

**Clash-free worlds first.** `follows` and `couldBe` add `:- clash(P).` and solve; if no world is left, they answer from every world, where the log's own clash shows as `both`. A one-world log answers as before. Reasoning by cases then holds: *A or B; if A then C; if B then C* gives C. *Maybe P* never clashes with *not P* or with *P*, so a later settled guess reads as an update: *maybe Alazun left* then *Alazun didn't leave* has no clash, and `couldBe` *did Alazun leave?* gives *no*. With a MAY holder, one world holds both views and the clash, the other does not, so `couldBe` gives *yes* and `clashes` none (m7 + m8, settled: *no* for `couldBe` of the stale reading). A `not P?` question is read as P with the answer flipped (`positive()`). Fewest clashes (`#minimize`) may come later.

### What stands
<a id="what-stands"></a>

The attack relation. Arguments are the log's readings, `arg(Id) :- on(Id).`; a nested reading (a hinge's clause, a quote) belongs to its reading. For each clash, the readings whose `fired` gives its two sides attack each other, both ways: `att(A, B) :- fired(A, P), fired(B, neg(P)).` and the reverse, with the `fits` form, the `view` form, and, for `notall(Id)` and `none(Id)`, the denying reading against each reading that fired an item. `rebut/2` covers plain claims, the `fits` form, the view form, `notall` and `none`, plain or inside a view (`view(H, notall(Id))`), and *always* over MAY against *never* (D13), `rebut(A, B) :- src(A, always(may(P))), src(B, never(P)).` with its `fits` form; `src/2` follows the generic ids (`requires`, `against`, `bans`, `widen`) back through `used`. A clash's premises are not attacked; a reading whose own atoms clash attacks itself. An open universal never fires against a stated denial, so it neither attacks nor is attacked. Under choices, attacks come from the brave `fired` atoms of a first run (the program plus `ATTACKS`), and the `att` facts feed an ASPARTIX program in a second run.

`stands(log, {semantics})` labels each translated reading `in`, `out` (attacked by a reading that is in) or `undec`; semantics are `grounded` (default), `stable` or `preferred`. `in` is skeptical (in every extension), and `credulous` is brave (in some). With every attack mutual, grounded is exactly the unattacked readings, and the semantics differ only once a one-way attack exists (a host's own `att` facts, which may come later). Example: c1 + c2 + c13 give `att(c1, c2)` and `att(c2, c1)`; grounded gives c13 in and c1, c2 undecided; preferred gives {c1, c13} and {c2, c13}.

## The edge

`Translation.left` lists each reading left out whole (a frame with no row), as `unread` is; a job answers from the rest and returns the list. A reading with a part no row used (a frame, link, SHARED detail, blank or member list) is left out with reason `unused` and the parts named; a question with one answers `beyond`. The translator also reports:

- A universal hinge's condition may name the member through a resume pronoun; the slots are built per stated member, so a member known only through `widen` gets no rule. A denied hinge on a universal (R4e decision 2: *not every cat* or *every cat, not if*) stays left. With MAY on the condition, a universal hinge's *only if* half has no back rule.
- `uwen` in a role and a say word's `-m` are the turn's speaker, `sp("…")`. `awan` is the turn's addressee, read from `LogEntry.addressees` (R4a-8, D16), never from the call frames on a reading: with exactly one addressee, a call's party as a term in a role (`yazozon` → `azozo`, `-r` through its antecedent) or another speaker `sp("…")`; with none or several (R4a decision 1), `listener(N)`, N the turn's place, which fits no other turn's. A call frame is used, and a reading with only a call (`yazozon.`) claims nothing. `zaya` is `we(S, A1, …, Ak)` (R4a-7): the speaker and the addressees, sorted by text, so one pair of people is one term whoever speaks; with no addressees `we(N)`. Whether `zayan vowurol.` also gives each member's act (R4a decision 2) is open: only the term is written. `match()` fits a speaker, listener or `zaya` term by the person its site names (`TermSite` with `we`, `Translation.site`), so `zawan` after a call to Azozon fits `zazozon`. A question has no turn: its `speaker`, `listener` and `we` are constants and fit no logged turn's.
- Two denial lists in one clause have no row.

Left out, by area (each stays in `left` or is named in an answer):

- **Say words.** A say word with a restrictor, or with a hinge and a universal together; a say word over `zul` or `zuam`; membership inside a say word in a holder's view; a whole-list denial or *no K* inside a say word or under a holder's own MAY.
- **Because and contrary-to.** *Because* under a say word, a holder's own MAY or a stance number; `hal`, `ham` or listed exceptions with *because*; MAY or a restrictor beside a holder, *only because* or *not because*; *or* beside any other frame; a condition with its own frame beside any other frame; contrary-to with a holder over the clause, a say word after the zone, or two of MAY, a hinge, a universal and a restrictor.
- **MAY.** A denied conditional with MAY; a carried holder on MAY beside any other frame; MAY over members or a whole-list denial beside any other frame; MAY with a say word beside another frame; MAY with an open universal or *no K*; MAY with `huam`, listed exceptions, or `hal` over MAY; MAY with a universal or restrictor beside a hinge, holder, *because* or zone.
- **Or.** `ue` and `oe` lists.
- **Numbers.** Other stance-number markers (`th_N`, `th#N`).
- **Fill questions.** `follows` and `couldBe` answer a fill question (`ask:fillAsk`) `beyond`, reason `fillAsk`: a yes or no job never answers one.
- **Links with no row.** Linker, polar, tag, discourse-hook, carried-channel and carried-NOTIONAL links: the reading is left as `unused` until a row says what each adds.
- **SHARED words.** A SHARED word other than a `/ɡ/` adjective on first-mention or named members (a scale, an equative, a collective, a count, a likeness, a hook): left as `unused`.

## Jobs

`solve.ts` exports each job as an async function over `log` (its `readings`). Options (`SolveOptions`):

| Option | Effect |
|--------|--------|
| `lexicon` | The parser's lexicon tables: compound heads for `widen`, in the program and in the question's match |
| `widen` | A compound holds of its head (row 12) |
| `defaults` | Everyday defaults for open universals (row 10) |
| `closedWorld` | Every term the log or the question mentions that does not hold is denied |
| `maxBytes` | The program size refused past; `MAX_PROGRAM_BYTES` (1 MiB) by default |
| `semantics` | `stands` only: `grounded` (default), `stable`, `preferred` |

| Job | Returns |
|-----|---------|
| `follows(log, question)` | `Answer`: cautious, what holds in every world |
| `couldBe(log, question)` | `Answer`: brave, what holds in some world |
| `clashes(log)` | `{clashes, left, refused?}`; each `Clash` has `atom`, `readings` (log order), `switches`, `english` |
| `giveUp(log)` | `{giveUp, english?, left, refused?}`: a smallest set of readings whose removal leaves a world with no clash. English: "Giving up X resolves every clash." |
| `stands(log, {semantics})` | `{semantics, stands, attacks, extensions, english?, left, refused?}`: `stands` is each reading with `label` (`in` / `out` / `undec`) and `credulous`; `attacks` is `[attacker, attacked]` pairs; `extensions` is one under grounded, at most `MAX_EXTENSIONS` otherwise. English: "Standing: …. Out: …. Undecided: …." See [What stands](#what-stands) |
| `whyNot(log, claim)` | `{clash?, left, verdict?: "beyond", refused?}`: the smallest clash the claim joins, the claim itself left out. English: "That cannot hold with X, Y." |

**`Answer`** is `{verdict, because, switches, left, english?}`. `verdict` is `yes`, `no`, `unknown`, `both` (the claim and its denial both follow), `beyond` (the question has a frame or part with no row, or is a fill question), or `refused` (program over `maxBytes`, or Clingo failed), with `english` saying why. `because` lists the reading ids behind the answer in log order; `switches` names each switch the answer used, and `couldBe` when a MAY question ran as `couldBe`.

**The question** goes in as one more reading with its claim switched off, but a first-mention noun's facts stay on as a witness, an arbitrary member of its kind, so *a cat sleeps?* reaches a closed `zual` universal as the matcher's `infer` step does. Only the lines the translator writes for those facts stay (`Translation.witnesses`), so a claim with the same shape, *a dog is caring?* as `isa(nm(..), K)`, never answers itself. A question with its own MAY (R4b-28, D6; `knowing.md#may`; `yel zazozon vabuvul thomal dalazun.`) asks whether it could be so: it runs without the MAY, as `couldBe`, whichever job is called. A holder's MAY on a question stays the holder's. A question over an *if*, *only if* or *iff* hinge asks for its conditional (row 19), matched through `Translation.conditionalFits`, not `match()`. Otherwise each `holds` atom is matched against the question with `match()`; `holds(neg(T))` gives *no* when `match(T, question)` succeeds; a range on a question noun is decided by `inRange` against the stated count.

**Clashes.** With one world, the readings come from walking back through `fired` / `used`, trimmed by one removal pass that re-solves. With more than one world (a choice rule), the switch atoms go free: QuickXplain finds one smallest clash, and a hitting-set tree (capped at 256 nodes) finds every smallest clash. Under choices, a set of readings clashes when none of its worlds is free of `clash` atoms. `Clash.atom` is an atom true in every world of the clash's readings if there is one, else one true in some world. `giveUp` is one optimization run: every `on(..)` a free choice, `:- clash(P).`, and a weak constraint per reading to keep it. `whyNot` runs QuickXplain with the claim held fixed; if the log clashes without it, it returns the smallest clash that contains it.

**Browser.** `solve-browser.ts` exports the same six jobs, each loading `solve.ts` on its first call; `browser.ts` re-exports them. A page that imports them needs `build.target: 'es2022'` (or `'esnext'`) in the site's Vite config, since the `clingo-wasm` worker uses top-level await.

The [loop](interpreter.md#the-loop) and host verdicts stay synchronous and never call the solver.

## CLI

```sh
node scripts/reading.mjs solve [--json] [--possible] [--defaults] [--closed] [--window N] FILE '<question>'
node scripts/reading.mjs clashes [--json] [--give-up] [--window N] FILE
node scripts/reading.mjs stands [--json] [--semantics grounded|stable|preferred] [--window N] FILE
node scripts/reading.mjs probe [--json] [--program[=full]] [--terms a,b] [--case N|LABEL] [--possible] [--defaults] [--closed] FILE
```

`solve` runs `follows` (`couldBe` with `--possible`) and prints `verdict`; `reply` (the spelled yes / no / I can't say, or *these cannot all hold* for `both`); `english` when refused or beyond; `why` (each reading id with `[at] speaker: text`); `switches`; `left`. `clashes` prints each clash with its atom and readings, `no clash` when none, and the set to give up with `--give-up`. `stands` prints each reading in, out or undecided, the attacks and the extensions. A refused run exits 1. Replies come from `clashReply` and `giveUpReply` in `reply.ts`.

`probe` (`probe.ts`) runs many independent cases from one FILE, each its own log: a line starting `---` starts a case (the rest of the line is its label), turn lines read as `log` reads them, `? text` asks with `follows` and `?~ text` with `couldBe` (`--possible` makes `?` use `couldBe`). Per case it prints turns that did not parse, `left` (reading, reason, frame key), `note`s, each smallest clash (readings and atom) or `no clash`, and each question's verdict, `because`, switches and its own `left`; `--program` adds the case's own program lines, without the generic rules and the holder's-view say rules every program shares (`--program=full` keeps them; `ownProgram` in `translate.ts` cuts them by the same constants that emit them), `--terms a,b` keeps only the program lines that name one of those predicates (`name(`; implies `--program`), `--case N` runs only the Nth case of the FILE (1-based; the header keeps its number) and `--case LABEL` the case with that label, `--json` one JSON object per line per case. The program is for debugging one case or confirming a new row's terms; batch probes run without it. `probe` has no expected-verdict syntax, so no option filters by verdict. A solve fixture reads as one case, as `translate.test.ts` reads it: `@ id` tags the next turn's readings (`t:0.0=s1`), `= English` is skipped. A failing case is reported in place; only a usage error or an unreadable FILE exits 1.
