# Realizer

<!-- retie: skip -->

**Status:** meaning view and round trip shipped; the realizer writes the bare clause, and the variant corpus is still to come  
**Design authority:** [`docs/grammar/`](../grammar/introduction.md) through the [interpreter's readings](interpreter.md#terms). The realizer writes Ageben for a reading; it never decides what a reading means.

The realizer takes a reading and writes an Ageben text that says the same thing. The round trip checks it: read a doc example, realize each reading, read the result again, and compare the two readings with [equal readings](interpreter.md#equal-readings). A pass shows that the reading holds the whole meaning of the text. A failure shows a place where the meaning still lives only in a word's spelling. This note owns the meaning view, the canonical choices, the round trip, the variant corpus and the list of gaps. The realizer is in `src/realize/`, and the round trip in `src/round-trip/`.

## Meaning view
<a id="meaning-view"></a>

The realizer never reads a reading directly. It reads the **meaning view**: a copy of the reading with its form taken out, made by `project` in `src/realize/meaning.ts`. If the realizer could see the parsed words, it could copy their spellings, and a round trip would pass without the reading holding the meaning. With the words taken out, any meaning missing from the reading shows up as a wrong word in the realized text.

**What the view keeps.** Everything a reading says about meaning:

- the reading's structure: the claim (verb, roles by letter, predicate, details, clause-join members), the frames, the stance lists, the links, and the nested readings of conditions, quotes, islands and asides;
- each frame's `family` and `key`, each detail's `kind` and `key`, and each term's `kind`;
- every `values` map, copied;
- the fields that tie meanings together: `party`, `hosted`, `content`, `inner`, `occasions`, `member` and `holderHost`;
- `order` and `unordered` as indices into the reading's frames, with each unsettled pair in text order. [Reader rule 3](interpreter.md#reader-rules) leaves the order of an unsettled pair open, so the view keeps the order the text gave and the realizer never picks one;
- links by kind and key, with the reading they point to (`to`), the frame they carry, and the terms and details they name;
- a pronoun's bind as the bind's kind, with its antecedent as a meaning-view term;
- the identities: a thing's roots, each named by its lexicon row's concrete sense (a listed compound stem as one root, a listed hook compound as its own row, and a root with no row by its spelling); a name as its root spelling; a plain adjective's, adverb's or degree word's root, as the reader's `values.root`; the root of a `-r` that reaches nothing earlier, as the pronoun's `values.root`; a literal's payload; and a number's stem (on a number detail, as the reader's `values.number`). These are spellings by design: a different root or name is a different thing, not a different way to say the same thing.

**What the view drops.** Everything that is form or a pointer into the parse:

- every parsed word (`LexWord`), so no spelling, ending or position reaches the realizer;
- construction ids, grammar anchors and word positions;
- the reading's `source` in the parse tree;
- the `unread` list. A reading with an unread construction is marked `unread`, and the round trip skips it with that reason, since its reading is known to be incomplete;
- in a link's records, the words: an answer keeps which question it fills and how many blanks, and a shared record keeps its role.

A test projects every doc example and fails on any object in the view that has a `raw` field, the mark of a parsed word.

**The import rule.** Files in `src/realize/` other than `meaning.ts` may import only these: `meaning.ts` and other files in the folder; the reading types (`src/interpret/types.ts`, as types only) and `src/interpret/read.ts`; the lexicon tables (`src/parse/classify.ts`, `src/lexicon-search.ts` and `src/lexicon-compounds.ts`, as types only, and `src/closed-roots.ts`); and the spelling path (`src/parse/gloss-inverse.ts`, and `spell` and `checkLine` from `src/interpret/reply.ts`). A test reads every such file's imports and fails on anything else. So `meaning.ts` is the only way from a reading to the realizer. Test files may import anything.

**Number glosses.** A number's stem is an identity the view keeps, so the realizer writes a number word's gloss label (`g-twelve`, `z-three`) itself, in `src/realize/numbers.ts`, from the stem and the markers the view records: a number term's `stem` and its `values.ending`, and a number detail's `values.number` (the stem in shorthand, `+3`) and `values.ending`. It does not import the glosser's `numberLabel`, which is outside the import rule. The spelling path spells that gloss, and `spell` keeps only a line that glosses back to it, so a label that drifts from the glosser's fails the round trip rather than passing silently.

## Canonical choices
<a id="canonical-choices"></a>

Where the grammar allows several forms with the same meaning, the realizer writes one. Each choice is a row here: what the realizer writes, the key of the reading part it writes it for, and the grammar anchor that allows the other forms. A choice must give a text that [equal readings](interpreter.md#equal-readings) finds the same as the original; when none does, the part is a gap.

| Choice | Key | Anchor |
|--------|-----|--------|
| The roles in the default order: subject, direct object, verb, then a plain extra noun (`z`, `d`, `v`, `b`) | `claim` | `clause.md#extra-nouns` |
| Roles whose nouns bring in a new member keep the order their frames cover each other in, the earlier word covering the later | `slot:newMember` | `clause.md#which-covers-which` |
| Adverbs, number adverbs among them, right before the verb, or before the predicate when the clause has no verb | `unit:h`, `lexReading:number` | `clause.md#adverbs-h` |
| The statement act `yal` left out when it is the turn's only act word | `edge:force` | `speech-moves.md#speech-act-beginner` |
| The body in the default order of its first act word: a question's verb second, a command's verb first, the receiver right after the verb; a statement or prohibition with the verb late | `edge:force` | `speech-moves.md#act-word-order` |
| Calls and reactions first, then a discourse hook, then the act words in the reading's order, then the body | `edge:force`, `edge:vocative`, `edge:interjection` | `firm-soft.md#firm-or-soft-act`, `speech-moves.md#vocative` |
| A tone mark that colors one word attached in front of that word, inside its unit's bracket; a mark that colors the rest of the sentence free-standing, first when it is the sentence's own and otherwise right before the first word it colors, every later word colored by it or by a later free-standing mark | `edge:tone` | `tone-marks.md#showing-your-tone` |
| A call's or a reaction's `gl-` and `/w/` words before its `/y/` word, its `/ɡ/` words after it | `edge:vocative`, `edge:interjection` | `more-turn-words.md#describe-turn-word` |
| A role pointer on `-r` written as the resume of the one it names, and a chain of `-r` resumes as the resume of the first mention; a role pointer that names a list, which has no resume, as the role pointer, from its part and pointer vowel | `anaphor:pointer` | `pronouns.md#role-pointers` |
| A new one on `-l` written as the noun it copies, on the new member's ending | `slot:newMember` | `pronouns.md#a-new-one` |
| A list as its members in the order the reading gives them, then one join that closes the fence, then the kind its members share or the words that describe each of them; a join with no items as the standalone join | `joinSeries:ua`, `slot:newMember`, `shared:distribute` | `joins.md#set-joins-and-rank-joins` |
| A range or in-clause hook right after the first phrase it joins, with its second phrase right after it | `hookJob:span`, `hookJob:clause` | `ranges.md#ranges` |
| An extra-noun hook and its landmark after the verb, after any plain extra noun; of two, the first after the subject and object and the second after the verb, so the second does not describe the first's landmark; the second hook of *from X to Y* right after the first | `hookJob:extraNoun` | `hooks.md#extra-noun` |
| A point-back hook after the verb, where an extra noun goes | `hookJob:resume` | `in-clause-hooks.md#hook-resume` |
| A hosted relation, its `/h/` word and `bl-` landmark, right before the verb, with the adverbs | `lexReading:joinRelation`, `overlay:locative:h`, `overlay:of_relation:h`, `overlay:exchange:h`, `overlay:proxy:h` | `clause.md#adverbs-h` |
| A contrary-to zone at the end of the clause | `hookJob:zone` | `contrary-to.md#contrary-to-stance` |
| A number, a fraction among them, in its preferred writing: spelled out with one digit or none (`gragel`, `gragem`), in shorthand with two or more (`g+12`, `g~+12`) | `lexReading:number` | `number-markers.md#writing-style-numeric-vs-spelled` |
| A polar word after the act words and before the body, the body in the order of the first act word, or of a statement when there is none | `edge:polar` | `questions.md#polar-particle` |
| A fill-ask's blank first in the body, with the word it completes (`el bar`, `abam zar`), and the rest in statement order | `edge:force` | `questions.md#fill-ask` |

## Round trip
<a id="round-trip"></a>

**The realizer.** `realize(view, tables)` in `src/realize/realize.ts` takes one reading of the meaning view and returns its morph gloss with the Ageben that `spell` writes for it, or a gap. A gap has a kind, the key it is filed under and a detail. The kinds:

- `noRule`: the realizer has no rule for this key yet;
- `missingValue`: the view lacks what the realizer needs to choose a word, a gap in the reader;
- `noSpell`: the gloss does not spell;
- `noParse`: the spelled line does not parse to one tree.

A gap is filed under the key of the reading's first part: its first frame's key, else its first claim detail's, its first stance list's or its first link's. A reading with none of these is the bare clause, filed as `claim`.

**The bare clause.** `src/realize/claim.ts` writes the claim: its verb, its `z`, `d` and `b` roles, its predicate and its plain adverbs, in the order of the [canonical choices](#canonical-choices). A role holds a `thing`, `speaker`, `listener`, `we` or `pronoun` term with its plain adjectives and their degree words (`src/realize/terms.ts`). A pronoun is written as the generic or topic pronoun by its `sort`, as the resume of the thing or special it names on `-r`, or as the noun it copies on `-l`; a role compound on `-r` is written as the resume of its event, from its `values.part` and `values.reach` and the verb its bind names, which spells only after that verb (`gap:noSpell` until a line is spelled with the turn's earlier lines); a tag pronoun is written from its `values.tag` and ending (`z-tag.A`, `z-←tag.A+O`, `d-←tag.A.part`, `z-tag.A.name`), and a recall on `-r` or `-m` parses only after its assignment, so it is `gap:noParse` until a line is spelled with the turn's earlier lines; an assigning tag (`slot:tag`) is written right after the term its link names in `tagged`, in the same role (`zodozel zwal`, `[[z-dog | z-cat | z-and.open] | z-tag.A]`), and a tag link that names no term is a gap; a share on `-m`, a resume pinned to a sense and a pronoun with no antecedent are still `noRule` gaps, and the pronoun's anaphor link is left to the reader, which binds the written pronoun again. A first-mention noun's new-member frame ([new member in a statement](../grammar/beginner/joins.md#new-member-in-a-statement)) is written by its noun alone, on the ending the frame records. A `list` term in a role, as the verb or as the predicate is written by `src/realize/lists.ts`: its members, then its join word, built from the list's `values.series` and `values.ending`, then its SHARED words: the kind its members share (`zual godozel`, *every dog*) or a plain word that describes each of them (`zal gamahum`, `val hahunom`). A hooked join writes its hook, from the list's `values.hook`, before the seam of its join word, and its landmark right after it as a `bl-` word (`zemxual bluwen`). A *respectively* link writes `w-respectively` before the join of the claim's one `a` list that is not its partner. The new-member frame of an and-list, a join's own binder frame (`joinSeries:ua`, also over a hook's landmark, `el bual`), the *no K* binder with the denial it holds (`zul godozel`) and a `u` join's denial frame are written by the list itself. A list of several fences writes each part in turn, from the part's own join values and SHARED words, each later fence closing the ones before it as one unit (`[[z-everything | g-cat] | z-not]`, [fence nesting](../grammar/intermediate/list-structure.md#fence-nesting)); only a first fence with no items is a standalone join. A standalone join read as a plain term (`blual`) is written as the standalone join of its `values.series`. *Respectively* closes the list its link names in `list`. A join with no items takes its standalone gloss (`d-none`, `z-everything`), or its listed one in a bare fragment (`zual.`), whichever spells. A role pointer that names a list is written as the pointer, from its `values.part` and `values.pointer`. A rank or tie fence's shared scale or equative word is written after its join as a kind word is, with a factor on it as an `/h/` number right after it (`zoel gelazem hradol`); a bar in the fence is its `/th/` or `/h/` word, the one letter the gloss index has a form of its root on the frame's ending for. A digitless scale word (`gral`, `hral`, `bral`) is written from the scale the reader records in `values.scale`, as its scale label (`g-amount`, `h-how-often`, `b-later`). A compound of two or more roots is written as its parts' labels joined at `-x-` (`z-peanut-x-butter`). A minus number of two or more right after a plain noun, or after a count, is written as the fraction it names (`g-third-of`; [fractions](../grammar/intermediate/measures-and-percent.md#fractions)), on **-l** only, since the fraction's gloss names no ending; a percent is still a `noRule` gap. A number adverb is written as an `/h/` number with the adverbs. A join on `-r` or `-n`, a hooked join that points back, a shared hook, a bar that is a built word (an ability, say or holder word), an unnamed landmark and an unnamed member other than the first under an and-list's frame (whose ending the view lacks) are still gaps. A claim detail that hosts a phrase is written by `src/realize/details.ts`: a range or in-clause hook as its word and the hosted phrase under the role letter the reader records in `values.part`; an extra-noun hook as its word and a `b` landmark; a hosted relation as its `/h/` word, from `values.gloss`, and a `bl-` landmark. A hook's word is its label by job, from `values.series` and `values.ending`, or a same-role word's own sense. A new-member frame on a hosted thing is written by that thing, on the ending the frame records. A discourse hook is its word first in the sentence and a point-back hook its word after the verb, each from its link's `gloss`; a contrary-to zone is `uom` and the one stance word its frame holds. A named hook (`oen`, `en`, which make the span a name), a hook with nothing hosted, a hook on a clause join, a list landmark, a zone with a holder or a stance of several words, and an unnamed relation landmark (whose ending the view lacks) are still gaps. A built word, as a term, the verb, the predicate or a detail, is written by `src/realize/built.ts` from what the reader records in `values.built` and its fields ([terms](interpreter.md#terms)), then its stem's label on the word's ending: a role word as its reach and part, then the stem, then any ability (`z-episode-agent-teach`, `g-episode-agent-authorship-able`); a hook prefix as its hook, `-x-`, the stem and any `-th-` reach (`z-against-x-fight`); a numeric prefix as its number, `.about` for the `mx` seam, `-x-` and the stem (`d-two-x-commitment`, `d-three.about-x-speech`, `g-quasi-x-friend`); a label seam as its stem, `-th-` and its reach (`v-misstate-th-role`); a listed hook compound as its own row (`v-leave`). A party a built word or a bar hosts is written right after it as a `bl-` word (`[v-misstate-th-pair | bl-Alazun]`). A hook prefix on a hook-compound stem and an unlisted hook compound are still `noRule` gaps; a role word with an ability vowel, a role word with a plural `-x` and a built resume on `-r` do not spell yet (`gap:noSpell`). Any other frame, a link or a stance list is still a `noRule` gap. A word's leaf gloss comes from the gloss index for its root, role letter and ending (`src/realize/words.ts`), so the realizer never writes an English label or a spelling itself.

**The walk.** `src/round-trip/round-trip.ts` reads each doc example as one turn of a log (`buildLog`), so links and pronouns cross its sentences. It projects every reading, realizes it, and joins the realized sentences in order. It then gives the example one verdict:

| Verdict | Means |
|---------|-------|
| `ok` | equal readings finds the original and the realized text the same, and realizing the realized text again gives the same gloss |
| `different` | equal readings finds them different; the trip keeps the first path where the two canonical forms differ, or `idempotence` when realizing again gives another gloss |
| `unsettled` | equal readings finds an unordered pair in the other text order |
| `gap:<kind>` | the realizer returned a gap for one of the readings |
| `skipped:<reason>` | not judged: the original does not parse (`noParse`), a reading has an unread construction (`unread`), or its readings did not project (`project`) |

A trip that is not a gap is filed under the key of its first reading, or of the first reading that differs.

**The ratchet.** `src/round-trip/round-trip-ratchet.json` holds the count of `ok` trips and, by key, the count of trips that failed (neither `ok` nor skipped). A failed trip counts once under the key of every part of every one of its readings (a reading with no parts counts as `claim`), not under the key it is filed under. That key moves as the realizer gets further into a trip, while a trip's part keys never change, so a key with no failures gains one only when an `ok` trip fails. Its test fails when the `ok` count falls, or when a key with no failures gains one. When the counts improve, the unit that improved them lowers the file to the new counts, which `npm run round-trip -- --ratchet` prints.

**The script.** `npm run round-trip` prints the counts by verdict, then each verdict's keys, each trip under the key it is filed under. `--save` writes them to the `tmp/` state folder, and `--diff` prints only the counts that changed since the save, as for `npm run sweep`. `--texts KEY …` lists the examples behind a verdict (`gap:noRule`), a key (`edge:force`) or a type that heads keys (`edge`). `--detail KEY …` prints the same trips in full (verdict, key, file, text, realized gloss and spelling, path and detail): the first 20, or `--limit N`, or at most N from each key with `--per-key N`, with all of them saved to `tmp/logs/round-trip-detail.txt`. `--tally KEY …` prints, per key, its trip count, then each reason with its count and one sample text with its file and line, the commonest first: the reason is the detail line after its key, or after its gloss with the gloss written `…` (`gloss does not round-trip: …`). It prints up to 8 reasons per key and saves all of them to `tmp/logs/round-trip-tally.txt`. `--ratchet` prints the current ratchet counts as JSON, and `--lower` writes them into `round-trip-ratchet.json`: `ok` only rises, each stored key only falls, and no key is added; it names any key that rose or is new.

<a id="probes"></a>
**Probes.** Before opening a realizer file, run `npm run -s outline -- src/realize --exports`: it lists each file's job and every helper it exports, with its line range and what it returns, in about 3k tokens (`src/round-trip` likewise). `npm run realize -- view TEXT …` reads each text as one turn and prints the parser's own morph gloss, each reading's meaning view as one JSON line, what the realizer writes for it (gloss and spelling, or its gap), and the trip's verdict as the round trip would judge it. `npm run realize -- spell GLOSS …` spells each morph gloss as the realizer does (`spellGloss`), or prints its `noSpell` or `noParse` gap. `npm run realize -- view --key KEY` views every text behind a round-trip key, as `--texts` lists them; `--has TEXT` keeps only the readings whose meaning-view JSON contains TEXT (`--has '"rhetorical"'`). It prints a count line and the first 10 texts, and saves all of them to `tmp/logs/realize-view.txt`. Triage of a key starts with `npm run round-trip -- --tally KEY`, which gives the reasons and a sample of each in one call; then `--detail KEY … --per-key 1` shows one trip in full from each key, and `view --key KEY --has FIELD` finds the readings that carry a field. Before work that depends on spelling or on a reader field, run one probe over a few samples: a gloss that does not spell, or a field missing from the view, is a blocker to plan around, not to find mid-unit.

## Gaps
<a id="gaps"></a>

This section will list each meaning the grammar pages leave unsaid where the round trip needs one, with a recommendation and its confidence. The realizer skips these until a page settles them.

- **A built word's front that is also a root's sense** (`spell`). A numeric prefix's kind label or a hook prefix's label can also be a root's sense, so `LABEL-x-STEM` names two words: `z-infinity-x-love` is both the numeric prefix `zrawaxolamal` ([numeric-derivation.md](../grammar/advanced/numeric-derivation.md)) and the mid-word compound `zenuroxolamal` (root `enuro`, *infinity*). The same holds for `grain` (`ogela`), `void` (`ohohu`), `origin` (`aha`) and the hook label `by` (`uvahu`). [Round trip](glosses.md#round-trip) wants one gloss per form, but its *one label per form* check covers roots only, so `spell` cannot choose and takes the compound. Options: reword the five lexicon rows; mark the prefix label in the gloss; or have `spell` prefer the built word. **Recommendation:** (medium) reword the lexicon rows, the fix that page already names for two roots that share a sense, and widen `glossCollisions` to check root senses against the numeric-kind and hook labels.
