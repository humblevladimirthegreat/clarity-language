# Tips from grammar-newcomer-rewrite P1: token spend

**Status:** IDEA, 2026-11-24.  
**Related:** [proposal-plans.md](../../../meta/procedures/proposal-plans.md), [proposals.md](../../../meta/procedures/proposals.md), [grammar-docs.md](../../../meta/grammar-docs.md#newcomer), `scripts/verify.ts`, `scripts/parse.mjs`, `scripts/lint-ageben-docs.ts`, `scripts/page-readers.ts`; the run reviewed is P1 of `grammar-newcomer-rewrite.md` (session 88add311, 3.9M weighted tokens: orchestrator 1.9M over 104 calls, six workers at 260k to 370k each).

Not design authority. Tooling and procedure only.

## Problem

Costs are weighted tokens (cache read 0.1×, 1 h write 2×, 5 min write 1.25×, output 5×), summed per cause over every agent it touched.

1. **A multi-page policy unit ran in the orchestrator (about 150k).** The plan marked U1 *Orchestrator*: two sections in `grammar-docs.md`, a cut in `claritish-style.md`, and two digest files. The orchestrator did it at main calls 7–8 and 28–43, at 83k to 104k context, about 226k for those calls. It added about 21k of slices and edits that the next ~60 orchestrator calls carried again (about 130k). In a worker at 30k to 45k context, the same work would cost about 60k more than a brief and a report. [proposal-plans.md](../../../meta/procedures/proposal-plans.md#one-session-or-several-subagents) already allows an orchestrator unit only for *a few edits on one page it can read in one slice*. U1 failed that test, and nothing caught it when the plan was written. This is also the main reason P1 took 104 orchestrator turns against the 40 the phase was planned for.
2. **Workers searched for the reading order (about 115k).** The newcomer rule says new examples use only *constructions taught on its page or earlier in reading order (check with `node scripts/find.mjs`)*. Neither the rule nor the briefs named `docs/grammar/.vitepress/lib/reading-order.ts`, and `find.mjs` has no order filter. U4 calls 10–19 grepped JSON, `src/` and `find.mjs --help` before finding the file (about 45k). U5 calls 8–13 did the same (about 40k), and A1 calls 14–18 too (31k). U3 then wrote an example the `learning-order` lint flagged as taught later, which cost one more edit-and-verify round (about 10k). This should have cost one 20-line read per worker, or nothing with a check that knows the order. The digests got the path at commit 8b9d7245, after A1, so S1 did not search. The general rule in grammar-docs.md still lacks it.
3. **The U2 brief left out `scripts/page-readers.ts` (about 105k).** U2 added a lint that reads grammar pages. The build's `page readers` step fails a new script that names a grammar path unless it is on `WHOLE_SITE`, and that file was not on U2's edit list. U2 spent calls 38–43 (66k at 65k to 70k context) finding out why and then stopped, as it should have. The orchestrator then made the one-line fix at main calls 49–52, about 14k a call at 110k context (about 56k). Listing the file in the brief would have cost about 10k in the worker.
4. **verify names a baseline-only failure as a failed job (about 80k).** The phase baseline held three open `page readers` errors (`src/parse/context-report.ts`). Every `verify` line, passing or not, ended with *failed jobs: page readers*, so each worker checked whether it had caused them: U3 calls 22–24 (26k), U4 calls 30 and 32 (15k), U5 calls 28–29 (16k), S1 calls 18–19 (15k), and A1 call 31 (8k). S1 and U4 even ran `git stash` and `npm run page-readers` against HEAD to be sure. It should have cost nothing: the baseline comparison already knows these keys are not new.
5. **The orchestrator read agent files to learn what a brief needs (about 45k).** Main call 13 read `.claude/agents/proposal-worker.md` whole (2k, carried for about 90 calls, 24k), and call 65 read `style-editor.md` (10k carry); together with the two calls that is about 55k. Step 2 of [running with subagents](../../../meta/procedures/proposals.md#running-with-subagents) already lists what a brief holds, and the paragraph below it lists what the agent files restate. The one thing the style-editor file adds is that the brief lists labels earlier pages already gloss, and that appears in neither. (The `run-reviewer.md` read, 8k, was for an unusual one-phase use and is left out.)

## Sketch

1. **Policy units go to a worker.** In [proposal-plans.md](../../../meta/procedures/proposal-plans.md#one-session-or-several-subagents), after the one-slice rule, add: *A policy unit that writes into more than one page, or reads more than one slice, is a `proposal-worker` unit. The orchestrator settles its decisions in the brief and reads only the report and `git diff --stat`.* Add the same test to [the plan section](../../../meta/procedures/proposal-plans.md#the-plan-section): each unit marked *orchestrator* names its one page and slice.
2. **Give the order check a tool.** Add `--at <page>` to `node scripts/parse.mjs --check-lexicon`. It reports, for each input, any construction whose home comes after that page, using the `learning-order` check in `scripts/lint-ageben-docs.ts`. With that, a writer checks a draft before splicing it. In the meantime, the *Examples stay within reach* bullet in [grammar-docs.md](../../../meta/grammar-docs.md#newcomer) changes *(check with `node scripts/find.mjs`)* to name `--check-lexicon --at` (or, until that exists, `reading-order.ts`'s `beginnerUnits`).
3. **Brief lists the registry for new page readers.** In [proposal-plans.md](../../../meta/procedures/proposal-plans.md#the-plan-section), under *the files each unit may edit*, add: a unit that adds a file under `src/` or `scripts/` that reads grammar pages also lists `scripts/page-readers.ts` (for `WHOLE_SITE`), or names the contract it imports from `src/page-contracts.ts`.
4. **Mark baseline-only failures.** In `scripts/verify.ts`, `failedNote` splits failed jobs into those with a new key and those whose keys are all in the baseline: *failed jobs: lint ageben; baseline only: page readers*. [Quiet verification](../../../meta/procedures/proposals.md#running-with-subagents) (step 5) and the agent files then say a job under *baseline only* is not the unit's to check.
5. **Close the brief contract.** In [proposals.md](../../../meta/procedures/proposals.md#running-with-subagents), step 2: add the style-editor's extra field (labels already glossed by earlier pages) to the style-gate bullet, and end the list with *This list is complete for every agent under `.claude/agents/`; do not open an agent file to write its brief.*

## Open questions

- **Sketch 2: a new flag, or only the pointer?** The pointer alone would have saved most of finding 2's 115k, but writers would still learn of a taught-later form only from `verify`, one round per mistake. **Recommendation:** add the pointer now and the `--at` flag when the next rewrite phase is planned, since every later phase repeats this check on every page. Confidence **medium**.
- **Sketch 1: rule text or a check?** No lint reads proposal plans, so a wording rule relies on the plan writer. A check that counts the *May edit* files of units marked *orchestrator* would catch U1, but it would be the first plan lint. **Recommendation:** wording only for now. Confidence **medium**.
- **Sketch 4: hide or mark?** Dropping baseline-only jobs from the line hides a job that is still red. **Recommendation:** mark them, as sketched. Confidence **high**.

## The review itself

The run-reviewer for this phase cost 728k over 62 calls, peaking at 112k.

- **The whole `--calls` listing went into context (about 70k avoidable).** Calls 6–7 ran `token-report --calls` for the whole session and printed its 330 call lines in two slices, about 13k tokens, which the next 55 calls carried (99k). Running `--agent <id> --calls` per transcript, as `.claude/agents/run-reviewer.md` step 2 says, or grepping the saved listing for costly rows, would have kept about 4k.
- **Two scratch scripts filled gaps in the report (about 25k, under the threshold but likely in every review).** `--calls` shows each result's carry but not each call's own weighted cost, and it cannot show a call's input or the reasoning before it. The review wrote `tmp/scratch/rr-calls.mjs` (calls in a range, with the text before each) and `tmp/scratch/rr-cost.mjs` (weighted cost per call) to measure calls like U4's, which cost 74k after a cache expiry.

**Sketch:** in `scripts/token-report.mjs`, give `--calls` a column with each call's own weighted cost and a `--top N` option that keeps the N costliest calls per transcript. Add `--show <agent>:<from>-<to>`, which prints each call's input and the assistant text before it, trimmed. Then in `run-reviewer.md` step 2, use `--top` first and `--show` in place of reading transcript lines.
