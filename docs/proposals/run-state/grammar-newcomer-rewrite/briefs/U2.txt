You are a proposal-worker. This is a code unit: a build lint and an outline flag. You write no
grammar prose.

## The item (from the plan)

- A build lint for agent summaries. It checks the format: one `<!-- Agent summary: … -->` comment
  directly under its heading, at most one per heading, never under Practice, See also, Gap,
  Examples or a read-by block. It checks coverage on stage pages, recipe pages and Claritish
  lessons: a page that has any summary has one under every teaching heading, per the placement in
  docs/meta/grammar-docs.md#agent-summaries. Until a later unit (L1) flips it, a page with no
  summaries passes. If the build's check of Ageben code spans skips HTML comments, run backticked
  forms in a summary through the same check.
- `npm run outline -- FILE --summaries` prints each heading's summary under it.
- Tests for both, and a row in docs/meta/doc-style.md#what-the-build-checks. The current tree passes
  the lint, Claritish lessons included.
- Report the line for AGENTS.md (the orchestrator adds it; never edit AGENTS.md yourself).

## The policy (read this section first, in full)

docs/meta/grammar-docs.md, section "## Agent summaries" (grep -n '^## Agent summaries'). It says
where summaries go per page kind, and their format. The Claritish placement is in

## Design notes from the orchestrator

- Page kinds: stage pages are docs/grammar/{beginner,intermediate,advanced}/*.md (teaching heading =
  every H3 except Practice and See also; H4s under Practice never count). Recipe pages are
  docs/grammar/english.md and docs/grammar/say-*.md (teaching heading = each heading that teaches a
  recipe; work out from the recipe track's shape in grammar-docs.md#recipe-track which headings
  those are, and say in your report what rule you chose). Claritish lessons are
  docs/grammar/claritish/*.md except index.md, the cheat sheet, the flashcards page, the editor
  page and the closing page (check which pages are lessons from the sidebar or the track policy in
  grammar-docs.md#claritish-track); teaching heading = each H2 except The gap, Examples and Practice.
- docs/grammar/claritish/index.md is the track's intro page, not a lesson: check format only (it
  has a summary under the H1 and one under "## The lessons"; a later unit moves them, so the lint
  must not fail on either now).
- Every Claritish lesson already has summaries, so coverage applies to them today. No stage or
  recipe page has any yet, so they pass.
- L1 later turns coverage on for every stage page, recipe page and Claritish lesson, whether or not
  the page has a summary. Make that one setting (for example a set of page kinds whose coverage is
  required), so L1 flips it with a one-line edit.
- "Directly under" means the next non-blank line after the heading, or after the `<a id>` line(s)
  that follow the heading.
- Look at how existing lints are written and wired before writing yours: scripts/lint-*.ts, the
  `jobs` list in scripts/build.mjs (about lines 99-119), src/lint/. Follow the closest existing
  pattern; a pure checking function under src/lint/ with its test, and a thin script, is the likely
  shape. Run its test with `npm test -- <file>`.
- scripts/outline.ts: list its declarations with `npm run -s outline -- scripts/outline.ts`, then
  read the ranges you change. The flag prints each heading's summary (indented) under the heading
  line; without the flag, output is unchanged.
- The Ageben code-span check is scripts/lint-ageben-docs.ts; find whether it skips HTML comments.
  If it does, check backticked forms inside agent summaries the same way the page's other code
  spans are checked. If the current Claritish summaries then fail (a drop-in shown as a bare

  Never add an allowlist or exemption to get the tree green: that is a decision for the

- docs/meta/grammar-docs.md: you may add only a link from the "## Agent summaries" section to the
  lint (one clause).
