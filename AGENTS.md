# Agalan

Constructed language and tooling that encode psychologically useful distinctions into vocabulary and grammar (compassion / rationality / empowerment themes: gratitude, bias awareness, authentic choice). Unambiguous syntax supports computational tools; phonology aims to be easy to sing.

Always call the language **Agalan** (never Clarity, Geran, Agelan, or other legacy names). Do not restate the English gloss from [`docs/grammar/introduction.md`](docs/grammar/introduction.md). The name is tied to the glasses root — [language-name.md](docs/meta/language-name.md). Grammar and in-scope editor blurbs show **only the current language**: current published spellings, current English names, current HTML ids. No former-name notes, silent alias fragments, or dual spellings “for old links” — [present the current language only](docs/meta/grammar-docs.md#present-the-current-language-only).

This repo is TypeScript tooling around the language docs and lexicon. A web UI may come later.

## Tooling notes

- Node ≥ 20.
- Tests run with **`npm test`** (Node's built-in runner via `tsx --test`). Vitest is intentionally **not** installed in this repo — never run bare `npx vitest` (it silently downloads the whole toolchain and hangs). To check whether a CLI is available locally, use `npx --no-install <tool>`, which fails fast instead of fetching from the registry; avoid bare `npx <tool>` for any tool this repo does not depend on.
- Language design work goes through `docs/grammar/introduction.md` (grammar design), `docs/grammar/why-agelan.md` (psychological purpose / feature criteria), `docs/grammar/core.md` and the linked grammar docs (and `TODO.md` until absorbed). Do **not** treat any parser implementation as design authority until it matches the docs.
- **Orthography:** actual Agalan has **no hyphen** after the PoS letter (`zugobon`, not `z-ugobo`); native text is **unicase lowercase** ([capitalization](docs/grammar/core.md#capitalization)) — capitals only inside foreign / opaque payloads that preserve another orthography’s casing; named reference is **-n** / **`@`**, not case. Foreign roots use `PoS<…>ENDING` (e.g. `d<english>l`, `z<Sam>n`); opaque spans take no ending after `>` (`d<sushi>`). Prefer published lexicon roots when the gloss matches; use **-m** for metaphorical gloss matches — see [core.md § Orthography](docs/grammar/core.md#orthography). Outside a sentence, prefix-less **root + ending** is [citation](docs/grammar/core.md#citation-forms) (not a default `/z/`); closed **`al` / `am` / …** stay [revisers](docs/grammar/revisers.md).
- **Utterance framing:** **`/j/`** = turn (vocatives, [polar stance](docs/grammar/questions.md#yes-no-polarity), marked speech act); **`/x/`** = same-speech-act forward motion (clause joins, linkers — inherit speech act). Default assertoric **`jal`** is **omissible** when recoverable (period, polar **-l** / **-m**, `/x/` continue, same-speech-act **`orodo`** dependent). Do not require leading **`jal`** on every example sentence. Polar confirm tags are a **second bare turn** after `.` (`…. jael.`), not same-sentence final `/j/`.
- After `npm run convert-word -- --lexicon`, run **`npm run retie-docs`** (dry-run) then **`npm run retie-docs -- --write`** to retie Agalan tokens in `docs/grammar/`. Never bulk-replace old roots across Markdown — that rewrites English substrings.
- After editing Markdown under `docs/` (or `AGENTS.md` / `TODO.md`), run **`npm run lint:md`** — it fails on unclosed `*` / `**`, slash-joined emphasis (`*a*/*b*`, which breaks Cursor’s rich preview with `italic,italic`), and broken internal links / anchors. Prefer spaces (`*a* / *b*`) or one span (`*a/b*`). Avoid nesting `**…**` inside already-bold text; in bold headings/bullets put forms in backticks only (`**Ranked (`e` / `ae`)**`, not `**ae**` inside).

# NOTE on evalutaing ideas:

dev effort required is not a meaningful CON against an idea. when presenting reasons againts an idea or option, it should only consider the effect on the end user, unless the technological effort is risky (requires a new library or AI might fail to implement it correctly). For example, needing to update a bunch of cross-references should not be given as a downside for adding a new language feature.
